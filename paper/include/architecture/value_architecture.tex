\subsection{Unified Data--Execution Architecture}
\label{sec:value_architecture}

The central design decision of the system is the elimination of the
boundary between stored data and executable code.  A single Value frame
serves simultaneously as a record in memory and as a self-contained
computation unit.  This subsection describes how the frame layout
supports both roles, how their interaction gives rise to computation,
and how Values compose into larger structures.

\subsubsection{The Data Plane}

The Token region (words 0--7, 512 bits) holds the raw content of a
Value: packed byte data derived from the input stream.  The Affinity
region (words 8--15, 512 bits) stores an 8-word locality-sensitive
fingerprint (\Cref{sec:entropy_routing}) that serves as the frame's
topological address in the distributed routing layer.  The bidirectional
link pointers (words 125--126) record predecessor and successor edges,
threading Values into sequences that preserve ingestion order.  The
unique frame identifier (word 127) provides a stable reference for
cross-frame addressing.

\subsubsection{The Execution Plane}

The Program region (words 16--23, 512 bits) holds up to 32 packed
instruction slots.  When a frame is submitted to the compute backend,
the backend reads the instruction at the current program counter,
decodes its four-bit opcode, applies the boolean truth table across
the specified source and destination spans, and writes the result
into the Signals region (words 24--31).

Program execution proceeds as a linear sweep: the Token region is split
into two operand spans $A$ and $B$, with $B$ rotated in 8-bit steps
at each instruction.  This rotation ensures that successive instructions
operate on different alignments of the input, extracting progressively
finer structural features.

\subsubsection{Interaction Between Planes}

The data and execution planes occupy the same address space within the
frame.  An instruction in the Program region can target any word in the
Token region, and conversely, a boolean operation applied to the Program
region can rewrite an instruction.  This bidirectional access has four
consequences.

First, a frame can \emph{inspect its own data}.  A program can read
token bytes, compare affinity fingerprints, or accumulate statistics
over the Token region using boolean operations, storing results in the
Signals region for downstream consumption.

Second, a frame can \emph{modify its own program}.  Because program
words are addressable data, an instruction can overwrite a later
instruction, enabling conditional behavior without explicit branch
primitives.

Third, when two frames interact through the compute backend, each
frame can read from the other's data and program regions.  One frame's
program can operate on another frame's tokens, compare affinity
vectors across frames, or copy instructions between frames.

Fourth, interaction can \emph{emit new Values}.  A program that
identifies derived structure---such as the residual after factoring
out shared content between two frames---writes it into a fresh frame
and deposits it into the routing layer.  The emitted Values carry their
own data, links, and programs, making them full participants in future
interactions.

\subsubsection{Values as Linked Sequences}

The Prev~ID (word 125) and Next~ID (word 126) pointers define a
doubly-linked chain over the population of Values ingested from a
data source.  During ingestion, the Machine (\Cref{sec:substrate})
links each new Value to its predecessor, preserving the temporal order
of the input stream.  These chains serve as the raw sequential structure
that the MarkovTrie (\Cref{sec:markovtrie}) learns from, while the
Affinity region provides the content-based routing signal that
determines \emph{which} trie a Value is stored in.
