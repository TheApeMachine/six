\subsection{Introduction}

Most modern computational systems separate three concerns: memory, execution, and learning. Data is stored in memory, programs define how that data is processed, and learning mechanisms adjust parameters to improve behavior over time. This separation is foundational across both classical software systems and modern machine learning architectures.

This work explores an alternative formulation in which these distinctions are collapsed into a single substrate.

We present a system where memory, execution, and program structure are unified. Data is stored in a structured memory space where each stored element is not only a passive representation, but also participates directly in computation. Execution does not proceed through an explicit sequence of instructions or through parameterized function approximation, but instead emerges from the resolution of queries over this memory substrate.

In this formulation, computation is driven by the interaction between stored structures. Given a partial input, the system resolves continuations by searching, composing, and transforming existing elements within the memory space. The result is a form of execution that is neither strictly symbolic nor statistical, but structural: behavior arises from how information is organized rather than from externally defined programs or trained weights.

A key consequence of this design is that the system can extend its own computational capabilities. When new patterns of execution are observed—such as successful transformations between states—they can be captured and reused as first-class operators. Over time, the system accumulates a library of reusable transformations derived directly from its own activity.

In addition to unifying memory and execution, the system also unifies experimentation and documentation. Experiments are defined programmatically and executed within the same substrate, producing structured outputs that are directly compiled into a formal research document. The resulting paper is therefore not a separate artifact written about the system, but a product generated by the system itself.

This work does not aim to outperform existing architectures on standard benchmarks. Instead, it introduces a different computational perspective: one in which memory is active, execution is emergent, and systems are capable of describing their own behavior through the artifacts they produce.
