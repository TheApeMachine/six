\subsection{Representation and Primitive Operations}
\label{sec:representation}

The system operates on a single primitive type called a \emph{Value}: a
fixed-width binary frame of 1024 bytes, organized as 128 sixty-four-bit
words.  All computation is expressed as transformations over Values using
the complete set of two-input boolean functions.

\paragraph{Frame Layout.}
Each Value is partitioned into contiguous regions with distinct roles,
specified by a configuration file that maps region names to word offsets
and bit widths.  The default layout is:

\begin{table}[h]
  \centering
  \caption{Value frame layout.  All offsets are word indices into the
           128-word frame.  Bit widths are given for the default
           configuration.}
  \label{tab:value_layout}
  \begin{tabular}{llrl}
    \toprule
    \textbf{Region} & \textbf{Words} & \textbf{Bits} & \textbf{Purpose} \\
    \midrule
    Tokens    & 0--7     & 512  & Raw input bytes, packed token data \\
    Affinity  & 8--15    & 512  & 8 independent SimHash projections \\
    Program   & 16--23   & 512  & 32 bitwise instruction slots \\
    Signals   & 24--31   & 512  & ALU output from program execution \\
    Reserved  & 32--124  & 5952 & Application-defined metadata \\
    Prev ID   & 125      & 64   & Link to predecessor Value \\
    Next ID   & 126      & 64   & Link to successor Value \\
    ID        & 127      & 64   & Unique frame identifier \\
    \bottomrule
  \end{tabular}
\end{table}

The Token region holds the raw byte content of an input datum.  The
Affinity region stores a locality-sensitive fingerprint used for
content-addressable routing (\Cref{sec:entropy_routing}).  The Program
region contains executable instructions that the multi-substrate backend
applies to the frame's own data.  The Signals region receives the output
of program execution, serving as a write target for the ALU.  The
Prev/Next/ID words thread Values into doubly-linked sequences that
preserve ingestion order.

This layout is not fixed at compile time.  A configuration file specifies
the word offsets and bit widths for every region, allowing the frame
geometry to be altered without modifying the runtime.

\paragraph{The Sixteen Boolean Operations.}
The instruction set consists of the sixteen two-input boolean
functions, each encoded as a four-bit truth table.  During execution,
pairs of bits drawn from two operand spans are used to index into the
truth table; the resulting bit is written to the destination.  Because
these operations are applied across \emph{spans}---contiguous runs of
bits within a frame---each instruction performs parallel boolean
evaluation over an arbitrary bit-width in a single step.

The sixteen operations partition into functional roles:

\begin{itemize}[nosep]
  \item \textbf{Identity and projection} (\texttt{A}=\texttt{0011},
        \texttt{B}=\texttt{0101}): output one operand, ignoring the other.
        Used for data movement between regions.
  \item \textbf{Equality testing} (XNOR, \texttt{1001}): returns all
        ones where source and destination bits match.  A span-wide XNOR
        producing all ones indicates a perfect match---the basis for
        pattern recognition across data regions.
  \item \textbf{Difference detection} (XOR, \texttt{0110}): returns
        ones where bits differ.  Identifies the structural delta between
        two frames.
  \item \textbf{Masking and gating} (AND, \texttt{0001};
        A-AND-NOT-B, \texttt{0010}): retains bits in the destination
        only where the source permits.  The inhibitor gate
        (\texttt{0010}) selectively removes bits, functioning as a
        permission filter.
  \item \textbf{Merging} (OR, \texttt{0111}): combines two spans,
        preserving all active bits from both.  Used for superposition of
        multiple identities into a single frame.
  \item \textbf{Constraint solving} (NAND, \texttt{1110}; NOR,
        \texttt{1000}): NAND yields positions where at least one input
        is inactive---the complement of the AND mask.
  \item \textbf{Conditional selection} (material implication,
        \texttt{1011}, \texttt{1101}): retains the destination where the
        source is active, and forces ones elsewhere.
  \item \textbf{Negation} (NOT-A, \texttt{1100}; NOT-B, \texttt{1010}):
        inverts a span.
  \item \textbf{Constants} (\texttt{0000}, \texttt{1111}): force a
        span to all zeros or all ones regardless of current content.
        Used for clearing and signaling.
\end{itemize}

No higher-level arithmetic or symbolic primitives are provided.  All
behavior is constructed by composing these operations across the
regions of one or more frames.

\paragraph{Program Execution.}
The ALU partitions the Token region into two operand spans, $A$ and $B$.
Span~$A$ is held steady; span~$B$ is rotated in 8-bit steps.  The
program counter advances through the Program region one opcode at a time,
applying the corresponding boolean truth table between $A$ and the
rotated $B$.  Results are emitted as Signal bits into the Signals
region.  Programs may set loop bits to request re-enqueuing for
iterative execution.

\paragraph{Instruction Encoding.}
Each instruction occupies a thirty-two-bit word with three fields: a
source operand, a destination operand, and a four-bit opcode.  Operands
may reference named regions, pointer dereferences, or fourteen-bit
immediate values.  A flag field distinguishes register references from
immediates.  An assembler translates a textual representation---one
instruction per line---into the packed binary form.  Extended instruction
words support memory-load markers for use in query and prompt firmware.

\paragraph{Programs as Data.}
Programs reside within the same frame that holds data.  The Program
region is addressable by the same boolean operations that act on the
Token region.  A frame may therefore carry stored information, an
executable program, or both.  Self-modifying behavior is a natural
consequence: an instruction can target another instruction in the same
program region.

\paragraph{Firmware.}
The system provides a library of pre-compiled programs called
\emph{firmware}.  Seven firmware types are defined:
\textbf{learn} (plasticity operations),
\textbf{bootloader} (register initialization),
\textbf{tombstone} (metadata zeroing via FALSE across structural words),
\textbf{viral} (program propagation to a partner frame),
\textbf{build} (structural assembly),
\textbf{query} (retrieval with extended memory-load instructions), and
\textbf{prompt} (input preparation).
Firmware segments compose into multi-stage pipelines through a chaining
mechanism described in \Cref{sec:firmware}.
