\subsection{Representation and Primitive Operations}
\label{sec:representation}

The system operates on a single primitive type called a \emph{Value}: a
fixed-width binary frame of 1024 bytes, organized as 128 sixty-four-bit
words.  All computation is expressed as transformations over Values using
the complete set of two-input boolean functions.

\paragraph{Frame Layout.}
Each Value is partitioned into contiguous regions with distinct roles.
The \emph{data region} (words 0--59) holds packed token identifiers
derived from the input byte stream, together with a unique frame
identifier and forward/backward linking pointers.  Words 61--63 store
execution \emph{state}: a slot index, a sequence index, and a running
accumulator.  Word~64 carries a 64-bit \emph{affinity} bitmask that
encodes topological routing preferences, and word~65 serves as a
\emph{link} pointer establishing directed edges to other Values.  A
256-bit \emph{gossip} signature occupies words 66--69, providing a
compact fingerprint for distributed routing.  Word~70 holds an 8-bit
time-to-live (TTL) counter in its low byte.

Seven general-purpose \emph{registers} (words 71--77) and a
\emph{program counter} (word~78) support execution.  A \emph{firmware
index} register selects which pre-compiled program occupies the
program region.  The remaining 49 words (79--127) constitute the
\emph{program region}, storing up to 98 thirty-two-bit instruction
slots.

This layout is not fixed at compile time.  A configuration file
specifies the word offsets and bit widths for every region, allowing the
frame geometry to be altered without modifying the runtime.

\paragraph{The Sixteen Boolean Operations.}
The instruction set consists of the sixteen two-input boolean
functions, each encoded as a four-bit truth table.  During execution,
pairs of bits drawn from a source and a destination are used to index
into the truth table; the resulting bit is written back to the
destination.  Because these operations are applied across
\emph{spans}---contiguous runs of bits within a frame---each
instruction performs parallel boolean evaluation over an arbitrary
bit-width in a single step.

The sixteen operations partition into functional roles:

\begin{itemize}[nosep]
  \item \textbf{Identity and projection} (\texttt{A}=\texttt{0011},
        \texttt{B}=\texttt{0101}): output one operand, ignoring the other.
        Used for data movement between regions and registers.
  \item \textbf{Equality testing} (XNOR, \texttt{1001}): returns all
        ones where source and destination bits match.  A span-wide XNOR
        that produces a block of all ones indicates a perfect match---the
        basis for pattern recognition across data regions.
  \item \textbf{Difference detection} (XOR, \texttt{0110}): returns
        ones where bits differ.  Identifies the structural delta between
        two frames.
  \item \textbf{Masking and gating} (AND, \texttt{0001};
        A-AND-NOT-B, \texttt{0010}): retains bits in the destination
        only where the source permits.  The inhibitor gate
        (\texttt{0010}) selectively removes bits, functioning as a
        permission filter---if the source is a mask, only unmasked bits
        in the destination survive.
  \item \textbf{Merging} (OR, \texttt{0111}): combines two spans,
        preserving all active bits from both.  Used for superposition of
        multiple token identities into a single frame.
  \item \textbf{Constraint solving} (NAND, \texttt{1110}; NOR,
        \texttt{1000}): applied across a span, NAND yields the set of
        bit positions where at least one input is inactive---the
        complement of the AND mask.  When one span encodes a set of
        rules and the other encodes a current state, NAND produces the
        set of positions not yet satisfied.
  \item \textbf{Conditional selection} (material implication,
        \texttt{1011}, \texttt{1101}): retains the destination where the
        source is active, and forces ones elsewhere.  Used for
        conditional patching: a template (source) selects which bits of
        the destination to preserve.
  \item \textbf{Negation} (NOT-A, \texttt{1100}; NOT-B, \texttt{1010}):
        inverts a span.  Converts a whitelist to a blacklist, or inverts
        a program's logic in a single pass.
  \item \textbf{Constants} (\texttt{0000}, \texttt{1111}): force a
        span to all zeros or all ones regardless of current content.
        Used for clearing and signaling.
\end{itemize}

No higher-level arithmetic or symbolic primitives are provided.  All
behavior is constructed by composing these operations across the
regions of one or more frames.

\paragraph{Computed Control Flow.}
Because the program counter and firmware index are stored in
addressable words, any boolean operation can target them.  A
conditional branch is implemented by computing a target address into a
register (using AND to mask the address with a condition bit) and then
writing the register to the program counter (using OR to merge it).  If
the condition is zero, the AND produces zero, and the OR leaves the
program counter unchanged; if the condition is one, the target address
propagates into the program counter.  This provides data-dependent
branching without a dedicated branch instruction.

\paragraph{Instruction Encoding.}
Each instruction is packed into a thirty-two-bit word with three fields:
a source operand, a destination operand, and a four-bit opcode.  Operands
may reference one of the seven general-purpose registers, the program
counter, the firmware index, or a fourteen-bit immediate value.  A flag
field distinguishes register references from immediates and pointer
dereferences.  The compiler translates a textual assembly language---one
instruction per line, each specifying source, destination, and
operation---into the packed binary form.

\paragraph{Programs as Data.}
Programs reside within the same frame that holds data.  The program
region is addressable by the same boolean operations that act on the
data region, and the program counter advances through this region during
execution.  A frame may therefore carry stored information, an executable
program, or both.  Self-modifying behavior is a natural consequence: an
instruction can target another instruction in the same program region.

\paragraph{Firmware.}
The system provides a library of pre-compiled programs called
\emph{firmware}.  Six firmware types are defined: \textbf{bootloader}
(register initialization), \textbf{affinity} (structural comparison and
value emission), \textbf{viral} (program propagation to a partner
frame), \textbf{shatter} (data decomposition via multi-pass AND),
\textbf{tombstone} (metadata zeroing), and \textbf{wipe} (data
zeroing).  Firmware segments compose into multi-stage pipelines
through a chaining mechanism described in \Cref{sec:firmware}.
