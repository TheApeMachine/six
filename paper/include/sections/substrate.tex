\subsection{Computational Substrate}
\label{sec:substrate}

Values do not execute in isolation.  The runtime organizes them into a
four-layer processing pipeline: the compute backend executes boolean
programs on individual frames, the MarkovTrie learns from sequences of
frames, the Kadabra DHT routes frames to specialized tries, and the
Field projects collective pressure across the network.

\paragraph{Multi-Substrate Backend.}
\label{sec:multi_backend}
A load-balanced \emph{Backend} abstracts the heterogeneous hardware
available on the host.  At initialization, the Backend probes for
NVIDIA CUDA devices, Apple Metal devices, and the always-present CPU,
registering each as a compute substrate.  All substrates implement a
common interface: \texttt{UniversalBitwise}, which reads a four-bit
opcode from a Value's current instruction, applies the corresponding
boolean truth table across the frame's operand spans, writes the result
to the Signals region, and advances the program counter.

The Backend selects a substrate for each batch through latency-aware
routing:
\begin{enumerate}[nosep]
  \item Probe the in-flight depth (number of pending jobs) on each
        substrate.
  \item Route the batch to the substrate with the lowest exponential
        moving average of service time.
  \item When all substrates are saturated, overflow to the CPU.
\end{enumerate}

CPU execution uses SIMD fast-paths for homogeneous instruction runs,
processing Values in tiles of 64.  The boolean truth table for each
instruction is applied via a four-term mask expansion:
\begin{equation}
  \text{out} = (A \mathbin{\&} B \mathbin{\&} m_0)
             \mathbin{|} (A \mathbin{\&} \bar{B} \mathbin{\&} m_1)
             \mathbin{|} (\bar{A} \mathbin{\&} B \mathbin{\&} m_2)
             \mathbin{|} (\bar{A} \mathbin{\&} \bar{B} \mathbin{\&} m_3)
  \label{eq:truth_table_expansion}
\end{equation}
where $m_0 m_1 m_2 m_3$ are the four bits of the opcode.  This
executes in constant time per 64-bit word, independent of which of the
sixteen boolean functions is selected.

\paragraph{Priority Spill Ring.}
A bounded multi-producer, multi-consumer ring buffer (capacity 65{,}536
slots) provides backpressure-free overflow storage for Values awaiting
compute.  The ring uses a lock-free enqueue/dequeue algorithm, ensuring
that no frame is dropped or blocked during concurrent access.

\paragraph{Machine.}
The \emph{Machine} is the top-level runtime orchestrator.  It binds
together the Kadabra node, a dataset source, and the ingestion loop.
During operation, the Machine reads the dataset in 64-byte chunks,
creates a Value for each chunk, computes the SimHash affinity
(\Cref{sec:simhash}), links the Value into a doubly-linked sequence
chain (setting Prev~ID and Next~ID), and publishes the Value to the
Kadabra DHT for affinity-based routing to the appropriate MarkovTrie.
After full dataset ingestion, the Machine triggers training on the
accumulated sequences.

\paragraph{Network Transport.}
A unified connection type, \emph{UniConn}, abstracts three transport
mechanisms: inter-process communication (IPC) via Unix domain sockets,
UDP multicast for local-network gossip, and QUIC for reliable wide-area
transport.  All three implement \texttt{io.ReadWriteCloser}, allowing
Values and FieldDigests to flow across process and network boundaries
using the same interface.  QUIC provides congestion control and
encryption for wide-area deployments; UDP provides low-latency local
broadcast for gossip protocol dissemination.
